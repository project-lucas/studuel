# Scolaria — guide agent

Application de soutien scolaire gamifiée (6e → Terminale), interface **entièrement en français**. Next.js 16 App Router + React 19 + Supabase (auth, Postgres, RLS) + Tailwind CSS 4.

## Commandes

```bash
npm run dev        # serveur de dev (localhost:3000)
npm run build      # build de production
npm run lint       # ESLint
npm run typecheck  # tsc --noEmit
npm test           # Vitest (tests unitaires de lib/)
```

## Architecture

- `app/` — pages App Router. Onglets principaux : `amis`, `reviser`, `defi` (central), `moi`, `tresor` — **leur contenu vit dans `app/<onglet>/onglet.tsx`, rendu par leur emplacement `app/@<onglet>/<onglet>/page.tsx`** (routes parallèles, onglets gardés vivants : voir la règle plus bas) et `app/<onglet>/page.tsx` ne porte que le titre ; plus `carnet` (« **Ma bibliothèque** », ex-« Mon carnet » : les dossiers de cours que l'élève écrit lui-même, ses capsules et ses fiches achetées, ouverte depuis le bouton de la carte de série de Réviser ; un dossier vit sous `/carnet/cours/[id]`, sa session sous `…/reviser`, l'ancien préfixe `/reviser/cours` est redirigé), `test` (sessions de quiz), `onboarding`, `login`, `compte`, `studio`, `parents` (espace parents : programme de vidéos du coach) et `admin` (studio de contenu, gardé par `is_admin`). Les mutations passent par des Server Actions (`actions.ts` à côté de la page). `app/api/` pour les rares routes API, `app/auth/callback` pour le retour d'auth Supabase.
- `components/` — composants React clients ; primitives dans `components/ui/` (shadcn/radix).
- `lib/` — **toute la logique métier est pure et testable ici** (srs, streak, xp, mastery, defi-modes, bosses, compagnon, tresor, capacity, habits, trajet…), chaque module avec son `*.test.ts` à côté. Clients Supabase dans `lib/supabase/` (`server.ts` / `client.ts`).
- `supabase/` — migrations SQL numérotées, **exécutées à la main** dans le SQL Editor du dashboard, jamais par un outil, toujours idempotentes. Rangées par nature depuis le 19/09/2026 : `supabase/schema/` (`schema.sql`, tables, RPC, RLS, droits, index, correctifs), `supabase/contenu/` (seeds : quiz, fiches, cours, capsules, exercices), `supabase/outils/` (diagnostic). Le numéro reste l'ordre d'exécution ; le NOM est la clé partout (`lib/migrations-lecture` trouve un fichier où qu'il soit). `supabase/README.md` dit ce qui reste à exécuter en production (mesuré par `npm run sonde`) ; `node _ASSOCIE/genere-a-executer.mjs` rassemble les absentes en un fichier à coller.
- `proxy.ts` — rafraîchit la session Supabase avant chaque rendu (remplace le middleware).

## Règles du projet

- **Logique métier dans `lib/`, pas dans les composants** : fonctions pures + tests Vitest. Les pages/actions ne font qu'orchestrer.
- **Sécurité par RLS** : le serveur n'utilise que la clé anonyme Supabase. Toute nouvelle table doit avoir ses policies RLS dans sa migration.
- **Nouvelle migration = nouveau fichier numéroté idempotent** dans `supabase/schema/` (structure) ou `supabase/contenu/` (seed) — ne jamais modifier une migration déjà exécutée ; l'inscrire dans `lib/sante.ts` (et `_ASSOCIE/sonde-base.mjs`) ; signaler à l'utilisateur qu'il doit l'exécuter à la main.
- **Dates** : jours = clés UTC `YYYY-MM-DD`, semaine commence lundi (index 0). Heures « élève » (créneaux de trajet) en Europe/Paris. Helpers dans `lib/time.ts`.
- **UI en français** uniquement (textes, labels, messages d'erreur).
- **Design system « crème & violet » (façon Duolingo)** : le monde visuel de l'onboarding `/bienvenue` étendu à toute l'app via les tokens sémantiques dans `:root` (globals.css). Fond **crème** `--background`, encre marine douce `--foreground`, **violet** `primary` = action/marque, **jaune solaire** `highlight`/`accent` = progression/récompense/XP, corail `destructive` = alertes, flamme ambre→orange = série uniquement. Typo **Nunito** (corps) + **Baloo 2** (titres). Utiliser les rôles sémantiques, **pas de couleurs hex en dur** hors flamme. Mondes scoping toujours en place : `.rev-*` (Réviser) et `.moi-*` (Moi) déjà violet+crème, `.onb-*` (onboarding), arène Défi : décor « colisée doré » peint (`lib/arena-background`) sur repli violet profond (`.defi-arena-bg`). Le mode sombre est neutralisé (`<html class="light">`). **Deux dérogations, assumées** : (1) sur l'arène `/defi`, la rangée de combat met le CTA **Duel 90 s en or** (`.olympe-gold`) entre deux tuiles sombres (`.arena-flank`) — sur un décor entièrement violet, le violet ne ressort pas, l'or si. Partout ailleurs l'or reste la couleur du gain. (2) le **tableau Progrès** de Marcel (`components/marcel/ProgresPanel.tsx`) juge la maîtrise au **feu tricolore** `success` → `warning` → `destructive` (vert/orange/rouge), et non violet/jaune : sur un écran de bilan, le jaune de la récompense se lisait comme une alarme de plus à côté du corail, et « acquis » en violet ne se distinguait pas de l'action. Ce sont des rôles existants de la DA, pas des couleurs inventées ; le violet y reste réservé aux boutons d'action (« +12 % »). Limité à ce tableau — les couronnes de Réviser gardent le violet.
- **Homogénéisation du 23/09/2026** (`docs/audit-design-2026-09-23.md` : seize chantiers, les cinq qui rapportent le plus sont faits). (1) **Un seul fond dans Réviser : le mur crème quadrillé** — plus de lavis ni d'aplat de matière sur le dossier, le chapitre, le cours, la fiche, l'exercice, le quiz et son score, et plus de feuille opaque `rounded-t-3xl bg-background` qui couvrait le mur ; **l'identité d'une matière tient à son médaillon** (`components/reviser/MedaillonMatiere.tsx` : la vignette sur plaque blanche), à ses billets et à ses liserés, jamais à un fond (la clé `header` de `subjectTheme` et `subjectRobe` ont disparu). Seul le bandeau d'une fiche d'encyclopédie garde sa teinte : c'est la dérogation des périodes. (2) **Une seule recette d'en-tête de page** : `components/reviser/EnTetePage.tsx` — retour rond blanc et action de droite, puis médaillon + H1 Baloo 2 `text-3xl` à taille FIXE + sous-titre gris, puis barre ou rangée de pilules — sur toutes les pages de Réviser, du carnet et des capsules ; `SubjectHeader` et `EnteteRayon` sont bâtis dessus ; plus de lien « ‹ Réviser », plus de H1 sans retour ; un onglet (sans retour) garde `PageHeader`, même H1. **Un seul H1 par page** : un player (À revoir, examen blanc) titre en h2. (3) **Violet pour toute action principale, et `Button` (`components/ui/button.tsx`) comme UNIQUE famille de gros bouton hors arène** — `size="xl"` pour LE gros bouton d'un écran, `shine` pour l'action unique ; `.onb-btn`, `.quiz-plaque`, `.quiz-pilule` et `.quiz-fond` n'existent plus (le chrono du quiz est une `.quiz-compteur` neutre) ; **casse de phrase** sur tous les boutons ; **plus de « GO »** : « C'est parti » en bouton large, « Partez ! » au compte à rebours ; **le vert et le corail sont des ÉTATS**, jamais une action (les verdicts de flashcards sont violet / contour) ; **jamais la teinte du jeu ni de la matière sur un bouton** ; l'or reste à l'arène, aux GAINS (« Encaisser ») et à **Studuel+** (sa plaque de l'arène, sa carte de la Boutique, « Offrir Studuel+ » des parents) : l'or est l'identité de l'abonnement. (4) **Tous les titres en `font-heading font-extrabold`** (onboarding compris, `.onb-title` est en Baloo 2) et **une seule convention de titre de section, `.titre-section`** (Baloo 2 extrabold, casse de phrase : « Mes matières ») ; les petites capitales espacées (`.surtitre`) ne servent qu'au sourcil d'un H1 de page ou à un petit label dans une carte, jamais à un titre de section ; les MAJUSCULES italiques restent l'identité du Défi et des jeux. (5) **Une seule recette de carte, en tokens** (`--carte-rayon` 1,5 rem, `--carte-ombre`, `--carte-liseret`, `--carte-socle` ; utilitaires `rounded-carte`, `shadow-carte`) : `.carte` (blanche, ombre douce), `.carte-plaque` (liseré + socle, la carte « jouet »), `.carte-sombre` (violet profond, encre `--ink-on-dark`) ; `Card` shadcn, `.rev-card`, `.moi-card` et le carnet lisent les mêmes tokens ; les cartes Clash Royale de la Boutique et les billets restent « au pixel ». (6) **Les modes du Défi** (Blitz, Chrono, Survie, Boss, Duel, Coop, défi du jour, duel en direct) rendent leurs réponses par `AnswerBoard` et n'écrivent juste/faux qu'en `success` / `destructive`. **Quatre décisions prises le 23/09/2026 sans Lucas, à confirmer ou à défaire** : (a) **les trois feuilles de l'arène gardent leur robe** — Modes et Quêtes sombres (elles préparent le jeu, elles portent la robe de l'arène), Classement clair (il se lit, comme l'onglet Amis) ; (b) **le feu tricolore est autorisé sur tout écran de BILAN** (tableau Progrès de Marcel, suivi des matières des parents, note du contrôle blanc et de l'examen blanc), en tokens `success` / `warning` / `destructive`, et interdit sur un écran d'action ou de navigation (l'urgence de l'accueil Réviser dit « proche » en `destructive`, « bientôt » en `warning`, « loin » en neutre — plus de vert) ; (c) **la teinte d'une matière n'est plus jamais un fond** (cf. 1) ; (d) **l'or de Studuel+ et d'« Encaisser » est gardé** (cf. 3).
- **Les outils de Marcel ont chacun leur teinte** (`data-teinte` + `.outil-*` dans globals.css) : le rail de `/marcel` mélange des modes du champ (fiche · rose, exercice · bleu, flashcards · vert) et des pages (mission · violet, méthode · indigo, oral · ambre, entraînement · corail, progrès · turquoise). **La couleur y est une IDENTITÉ, pas un rôle** — elle ne touche que l'icône, sa pastille et le liseré de la carte ; tous les boutons d'action restent violets. Huit cartes violettes ne se distinguaient pas les unes des autres, et il fallait relire chaque titre à chaque fois. C'est une dérogation étroite et documentée, comme l'or de l'arène et le feu tricolore du tableau Progrès : elle ne s'étend pas aux fonds, aux textes ni aux boutons.
- **Un dossier de matière ne montre que son programme** : les chapitres officiels en cartes (`chapters.theme`), leurs fiches dessous, rien à côté — ni axe culturel isolé, ni fiche de synthèse maison, ni chapitre hérité d'un vieux seed. Le design de référence et la marche à suivre sont dans `docs/template-matiere.md`.
- **L'ENCYCLOPÉDIE est le troisième rayon du dossier Histoire-Géo** (`/reviser/histoire-geo/encyclopedie`, onglet ajouté par `modesFor` via `lib/encyclopedie/matieres`) : deux volets — **personnages** et **événements** —, une barre de recherche, des filtres par période et par classe. **LA CITATION EST LE CŒUR DE LA FICHE, pas un ornement** : « Je suis née pour cela » se retient mieux qu'une date de naissance, se recopie en copie et donne une prise sur quelqu'un dont on ne savait rien ; une fiche SANS citation est refusée par `lib/encyclopedie/valider.ts`, et c'est la citation que la carte de la liste montre avant tout le reste. Une fiche se lit par étages — accroche, citation, « en 30 secondes », récit, frise, « à retenir » — et on peut s'arrêter à n'importe lequel. Les événements portent toujours les MÊMES trois colonnes : POURQUOI (`causes`) → CE QUI SE PASSE (`recit`) → CE QUE ÇA CHANGE (`consequences`). **Le contenu vit en TypeScript** dans `lib/encyclopedie/contenu/` (un lot = un fichier + une ligne du registre, régénérable par `node scripts/encyclopedie-registre.mjs`) et **pas en base** : il est le même pour tous, il ne change jamais, et une lecture Supabase par ouverture de fiche coûterait 60 ms pour rien — la liste ne coûte qu'UNE lecture (le profil), la fiche AUCUNE. **Le corpus ne descend jamais dans le navigateur** : le client ne reçoit que les APERÇUS (`lib/encyclopedie/apercu.ts` : nom, dates, citation tronquée, clés de recherche déjà normalisées), et la recherche est synchrone, sans réseau, à chaque touche — **elle répond comme un élève tape** : sans accent ni apostrophe (« jeanne darc »), les rois en chiffres arabes (« louis 14 », « napoleon 3 »), et une date cherchée EN ENTIER (« 14 » ne doit pas remonter 1483). **La teinte d'une période est une IDENTITÉ, pas un rôle** (dérogation assumée, comme les outils de Marcel et les capsules) : elle habille le médaillon, le bandeau et le liseré, jamais un bouton — et **aucune période n'est violette**, le violet restant la couleur de ce qui se clique. Les fiches déjà lues sont cochées depuis le navigateur (`lib/encyclopedie/lues.ts`, `useSyncExternalStore`) : l'encyclopédie ne donne ni XP, ni gemmes, ni couronnes — on la lit par curiosité. **Le ton est une règle, pas un goût** : les rois de France et les figures chrétiennes sont racontés dans leur temps, pour ce qu'ils ont bâti et tenu, sans ironie ni procès rétrospectif ; la Révolution est développée entièrement et par ses mécanismes (les ministres réformateurs renvoyés, la dette de la guerre d'Amérique, le prix du pain et les accapareurs, la bourgeoisie d'avocats qui remplace la noblesse, l'argent qui prend la place de la naissance). Le guide de rédaction est `docs/encyclopedie.md`, le sommaire des identifiants `docs/encyclopedie-sommaire.md`, et `lib/encyclopedie/contenu.test.ts` refuse une fiche hors contrat, un renvoi mort ou un lot écrit mais non branché.
- **Le duel classé est une COURSE** (`/defi/programme/[matiere]`, `components/duel/*`, logique pure dans `lib/duel/*`) : deux barres qui se remplissent à 1 000 points, la première pleine gagne, 90 s max, une question dorée (×2) par course, le rival répond EN MÊME TEMPS (ligne de temps rejouée). L'adversaire est un **vrai élève du même niveau rejoué** (table `duel_replays`, migration 351) et, à défaut, un **robot du banc** (`lib/duel/bots.ts`, 24 rivaux à tempérament, toujours marqués « IA », jamais d'établissement réel). Le serveur (`lib/duel/fin-course-server.ts`, appelé par la route **`/api/duel/fin`** — pas une Server Action : Next les exécute une par une, un envoi bloqué par le réseau bloquait toute relance) refabrique le rival depuis la graine ou la base et n'accorde les trophées que sur SON verdict — les points ne sont jamais stockés, seuls les pas le sont. **Une course porte un identifiant** (`courseId`, tiré par l'écran) : l'envoi se relance sans risque (délai 12 s, deux relances, bouton « Réessayer » — `lib/duel/envoi.ts`) et la transaction `duel_course_enregistrer` (migration **374**) paie tout ou rien, jamais deux fois. Le rival rejoué est celui de la **version** de trace affrontée (la ligne garde la précédente) ; une trace ne va jamais plus vite qu'un joueur (`sanitizeSteps` recule un pas trop tôt : écart ≥ correction + réflexion). **La fin de course ne revalide rien** : `revalidatePath` dans une action re-rendait la course elle-même et vidait le cache de tous les onglets à chaque revanche ; l'arène et les onglets se relisent UNE fois, au premier écran hors course (`lib/apres-course`, `components/PrechargeurOnglets`). Le choix de matière (roulette + bouton DUEL, trophées par matière × jeu) ne change pas. La course est en plein écran (`lib/quiz-chrome`) et sonne « cuivre » ; ses sons propres vivent dans `lib/duel/audio.ts` (`duelSfx`).
- **LES CINQ ONGLETS RESTENT MONTÉS, COMME CHEZ CLASH ROYALE** (23/09/2026 ; mesures, architecture et pièges dans `docs/latence.md`, cinquième lot). Chaque onglet a son EMPLACEMENT dans la mise en page racine (routes parallèles `app/@defi`, `@reviser`, `@amis`, `@moi`, `@tresor`, chacun avec un `default.tsx` vide) ; son contenu est `app/<onglet>/onglet.tsx`. Lors d'une navigation dans l'app, Next garde un emplacement que l'URL ne vise plus, et `components/OngletsVivants` montre celui de l'URL EXACTE (`ongletVivant`, lib/nav-tabs — une sous-page comme `/reviser/maths` est une page ordinaire, dans `children`) et cache les autres avec `<Activity>` : DOM, état et défilement conservés, effets suspendus, portails masqués. Changer d'onglet ne reconstruit plus l'écran, il le RÉVÈLE ; seule la première visite le construit. **La barre répond au doigt** : la plaque suit l'onglet touché (`cheminAffiche`), pas l'URL, et glisse par `transform` ; toucher l'onglet actif remonte en haut. Règles qui en découlent : (1) un écran TRANSITOIRE d'onglet (feuille, rideau, menu dont l'état est local) appelle `useFermeAuMasquage(setOuvert, false)` (valeur « fermée » STABLE : une primitive, ou une constante de module pour un objet) — il se referme au retour, avant la première image (refermer au masquage ne marche pas : mise à jour différée dans un arbre caché) ; (2) **jamais d'identifiant SVG écrit en dur** (dégradé, masque) : `useId()` — un dégradé défini dans un onglet caché ne se peint pas ; (3) un `querySelector` vise l'exemplaire VISIBLE (`premierCentreVisible`, lib/hud-gains) — un onglet caché garde ses éléments dans le DOM ; (4) un onglet ne rend rien qui dépende de l'URL précise ni des paramètres de recherche : il vit sous toutes les URL ; (5) un rafraîchissement ou une action qui revalide rafraîchit aussi les onglets gardés (une requête par onglet, en arrière-plan, sans retarder l'action).
- **Les onglets sont préchargés par `components/PrechargeurOnglets.tsx`, un par un** (règle dans `lib/precharge-onglets.ts`, mesures et protocole dans `docs/latence.md`). Ne jamais remettre `prefetch` sur les liens d'onglet : en rafale, l'app se sature elle-même (503). Le préchargeur se tait sur tout écran plein écran (course, quiz, dictée) : la course passait pour l'onglet Défi (préfixe) et lançait quatre rendus d'onglets en pleine partie. **On ne change d'onglet qu'en touchant son icône** : le balayage horizontal entre onglets (SwipeTabs) a été retiré le 18/09/2026, le contenu qui suivait le doigt montrait la latence de la page suivante — ne pas le remettre. Et un module `lib/*.ts` importé par un composant client n'importe ni `lib/catalog` ni `lib/supabase/*` — sinon supabase-js (57 Ko) part dans le bundle : scinder en `*-server.ts` (ex. `lib/mastery-server.ts`).
- **PostgREST rend AU PLUS 1 000 lignes par réponse, sans le dire** (réglage Supabase « max rows », défaut). Le catalogue a dépassé ce seuil le 05/09/2026 (2 323 chapitres, 2 340 quiz, 18 262 questions) : des matières pleines s'affichaient « Bientôt », la maîtrise se calculait sur 43 % des quiz. **Toute lecture sans filtre, ou filtrée par classe ou par matière, passe par `toutLire`** (`lib/postgrest-pages.ts`, pur, testé) avec un `.order('id')` ; pour compter, préférer une RPC en base (ex. `catalog_quiz_question_counts`, migration 354).
- **L'écran de chapitre range ses supports sous TROIS VERBES** (`lib/subject-template.ts` → `groupSupports`, rendu par `components/reviser/SupportChips.tsx`) : **Apprendre** (Cours, Fiche), **Mémoriser** (Flashcards, Mes erreurs), **Se tester** (Quiz, Exercice, Moi vs IA). Le Défi solo de leçon n'existe plus (il rejouait les questions du quiz sous un troisième habillage ; le mot « Défi » ne désigne plus que l'arène). **L'Exercice** est un faux contrôle noté sur 20 (`lib/exercice.ts` pur, `app/reviser/[subject]/[chapter]/exercice/*`, tables `chapter_exercices` partagée et `chapter_exercice_reponses` par élève, migration 360) **à trois niveaux** (Facile · Moyen · Difficile, migration 364) : chaque fiche porte des sujets **écrits d'avance** avec leur corrigé type (`origine = 'catalogue'`, 6e complète en migration 365), que l'IA ne fait que **corriger** en s'appuyant sur ce corrigé ; elle ne **rédige** un sujet que pour « Un autre sujet » ou une fiche sans catalogue. Le corrigé ne part jamais vers l'élève avant sa copie (`exercicePublic`). L'Exercice est **réservé à Studuel+** (le premium ne débloque pas les fiches en gemmes : il accélère seulement le gain de gemmes). **« Moi vs IA » est un bloc réservé** (`bientot: true`, aucune page derrière) laissé en place pour que Lucas décide s'il y revient. Le client IA, le quota et le lecteur JSON sont dans `lib/ia-server.ts`, partagés avec le carnet.
- **Depuis le 18/09/2026, la tuile Exercice ouvre un CAHIER D'EXERCICES** (le contrôle blanc ci-dessus devient la dernière marche du chemin, `/exercice/controle`, et reste l'écran d'un chapitre sans cahier) : **trois exercices par chapitre faits comme une page de manuel** — mise en situation, 1 à 3 **documents** (carte, graphique, texte, schéma, frise, figure, droite graduée, chaîne, circuit électrique, fiche « authentique », dialogue, Scratch, horloge, pavé), questions dessous —, notés **★ / ★★ / ★★★** (l'exercice 1 ne fait peur à personne), **débloqués l'un après l'autre**, qui rapportent **5 / 10 / 15 gemmes** et 20 / 35 / 50 XP à la première réussite. Ce n'est pas un quiz : on répond en touchant le document (`zone`), en tapant un nombre, en rangeant, en reliant, en complétant. **Le serveur est seul juge** : réponses et explications dans `exercices_cles` (aucune policy), deux essais par question (2 points du premier coup, 1 au second ; coup de pouce au premier raté, correction au second), réussi à la moitié des points (`exercice_commencer` / `exercice_verifier` / `exercice_terminer`, migration **372** ; `exercice_juger` et `exercice_normaliser` sont les MIROIRS de `lib/exercices/juger.ts` et `normaliser.ts`). Moteur pur dans `lib/exercices/` (types, validation, compilation, jugement, progression), écran dans `components/exercices/` (module CSS `manuel.module.css` : **la palette des DOCUMENTS est une dérogation assumée** — l'eau est bleue, la forêt verte, le désert sable, Scratch a ses couleurs —, elle porte une information, jamais une action ; les boutons restent violets). Fonds de carte projetés par `scripts/cartes-exercices.ts` (Natural Earth + IGN) dans `lib/exercices/cartes/`. **Le contenu s'écrit en JSON** dans `contenu/exercices/<niveau>/<matière>[.<lot>].json` selon **`docs/exercices-manuel.md`** (le guide de rédaction), se relit par `scripts/exercices-valider.ts` et `lib/exercices/contenu.test.ts` (chaque bonne réponse rejouée), se joue sans compte sur `/dev/exercices` (développement seulement), et part en base par `scripts/exercices-sql.ts` (migrations 375+, dans `supabase/contenu/`).
- **Quiz et flashcards se jouent AU CHRONO, comme le duel** (`lib/quiz-chrono.ts` pur) : un budget pour la manche (12 s/question, borné 30–180 s), une bonne réponse rend 3 s, et **à zéro la manche est abandonnée sans rien écrire** (ni session, ni note, ni SRS) — pas de « fausse session » qui gonflerait la maîtrise. Le chrono du quiz se suspend pendant la lecture de la correction. Les verdicts des flashcards (« je le savais / à revoir ») alimentent la file « À revoir » sous l'identité de la question du quiz.

## Navigation du code (graphify — par défaut)

Un graphe de connaissances du projet vit dans `graphify-out/` (code + docs). **Avant de fouiller le code pour une question d'architecture** (« où est géré X », « qui appelle Y », « qu'est-ce qui dépend de Z »), **interroge le graphe** au lieu de lire/grep des dizaines de fichiers — c'est plus rapide et ça économise des tokens :

```powershell
& (Get-Content graphify-out\.graphify_python) -m graphify query "ta question"
```

- Le graphe **se rafraîchit tout seul après chaque commit** (hook `post-commit`, code uniquement, **zéro token**). Reconstruire à la main : `graphify update .` (code seul, gratuit) ou `/graphify` (complet, ré-inclut les docs).
- Graphe **local** (dans `.gitignore`). Après un nouveau clone, réinstaller les hooks : `graphify hook install`. S'il manque, le construire une fois avec `/graphify`.
