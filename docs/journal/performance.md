# Journal — Performance, onglets vivants, fiabilité

Paragraphes déplacés mot pour mot depuis CLAUDE.md le 16/10/2026 (il dépassait la limite de chargement). Ils gardent leur valeur de référence : décisions de Lucas, pièges, chemins de code. Un paragraphe plus récent peut en REMPLACER un plus ancien : il le dit.

- **LES CINQ ONGLETS RESTENT MONTÉS, COMME CHEZ CLASH ROYALE** (23/09/2026 ; mesures, architecture et pièges dans `docs/latence.md`, cinquième lot). Chaque onglet a son EMPLACEMENT dans la mise en page racine (routes parallèles `app/@defi`, `@reviser`, `@amis`, `@moi`, `@tresor`, chacun avec un `default.tsx` vide) ; son contenu est `app/<onglet>/onglet.tsx`. Lors d'une navigation dans l'app, Next garde un emplacement que l'URL ne vise plus, et `components/OngletsVivants` montre celui de l'URL EXACTE (`ongletVivant`, lib/nav-tabs — une sous-page comme `/reviser/maths` est une page ordinaire, dans `children`) et cache les autres avec `<Activity>` : DOM, état et défilement conservés, effets suspendus, portails masqués. Changer d'onglet ne reconstruit plus l'écran, il le RÉVÈLE ; seule la première visite le construit. **La barre répond au doigt** : la plaque suit l'onglet touché (`cheminAffiche`), pas l'URL, et glisse par `transform` ; toucher l'onglet actif remonte en haut. Règles qui en découlent : (1) un écran TRANSITOIRE d'onglet (feuille, rideau, menu dont l'état est local) appelle `useFermeAuMasquage(setOuvert, false)` (valeur « fermée » STABLE : une primitive, ou une constante de module pour un objet) — il se referme au retour, avant la première image (refermer au masquage ne marche pas : mise à jour différée dans un arbre caché) ; (2) **jamais d'identifiant SVG écrit en dur** (dégradé, masque) : `useId()` — un dégradé défini dans un onglet caché ne se peint pas ; (3) un `querySelector` vise l'exemplaire VISIBLE (`premierCentreVisible`, lib/hud-gains) — un onglet caché garde ses éléments dans le DOM ; (4) un onglet ne rend rien qui dépende de l'URL précise ni des paramètres de recherche : il vit sous toutes les URL ; (5) un rafraîchissement ou une action qui revalide rafraîchit aussi les onglets gardés (une requête par onglet, en arrière-plan, sans retarder l'action).

- **Les onglets sont préchargés par `components/PrechargeurOnglets.tsx`, un par un** (règle dans `lib/precharge-onglets.ts`, mesures et protocole dans `docs/latence.md`). Ne jamais remettre `prefetch` sur les liens d'onglet : en rafale, l'app se sature elle-même (503). Le préchargeur se tait sur tout écran plein écran (course, quiz, dictée) : la course passait pour l'onglet Défi (préfixe) et lançait quatre rendus d'onglets en pleine partie. **On ne change d'onglet qu'en touchant son icône** : le balayage horizontal entre onglets (SwipeTabs) a été retiré le 18/09/2026, le contenu qui suivait le doigt montrait la latence de la page suivante — ne pas le remettre. Et un module `lib/*.ts` importé par un composant client n'importe ni `lib/catalog` ni `lib/supabase/*` — sinon supabase-js (57 Ko) part dans le bundle : scinder en `*-server.ts` (ex. `lib/mastery-server.ts`).

- **PostgREST rend AU PLUS 1 000 lignes par réponse, sans le dire** (réglage Supabase « max rows », défaut). Le catalogue a dépassé ce seuil le 05/09/2026 (2 323 chapitres, 2 340 quiz, 18 262 questions) : des matières pleines s'affichaient « Bientôt », la maîtrise se calculait sur 43 % des quiz. **Toute lecture sans filtre, ou filtrée par classe ou par matière, passe par `toutLire`** (`lib/postgrest-pages.ts`, pur, testé) avec un `.order('id')` ; pour compter, préférer une RPC en base (ex. `catalog_quiz_question_counts`, migration 354).

- **L'app installée démarre sur un écran de lancement STATIQUE** (24/09/2026, Lucas : « quand je clique sur l'app, je tombe sur l'icône ») : `start_url` = `/lancement.html` (`public/lancement.html`, servi par le CDN, exclu de `proxy.ts`) peint l'illustration et la barre du rideau en quelques dizaines de ms — Android garde son propre rideau (l'icône) jusqu'au premier pixel, et `/` attendait un démarrage à froid puis une redirection. Il note l'heure du lancement (`sessionStorage`, `CLE_LANCEMENT`) et part vers `/defi` (cookie de session) ou `/` ; le rideau de l'app (`SplashScreen`) PREND LA SUITE sans repartir de zéro (`depuisLancement`, et `scriptSuiteLancement` décale l'animation CSS avant l'hydratation, en n'écrivant que dans `<head>`). Pas de texte sur la page statique (les polices de l'app ont des noms hachés) : le logo arrive avec le rideau de l'app. À resynchroniser si le rideau change.

- **L'app se joue à la VERTICALE et SANS ZOOM** (22/09/2026) : `orientation: portrait` dans le manifeste, `viewport` sans zoom (`maximumScale: 1`, `userScalable: false`, `viewportFit: cover` — un pincement sur une table de jeu laissait l'écran décalé), et `components/GardePortrait.tsx` : tentative de `screen.orientation.lock('portrait')`, puis un rideau CSS « Tourne ton téléphone » (`.garde-portrait`, seulement écran tactile + paysage + moins de 600 px de haut : jamais sur une tablette ni un ordinateur).

- **Une animation en continu n'anime QUE `transform` et `opacity`, avec des valeurs littérales** (23/09/2026, mesuré en production) : une ombre, un fond ou un filtre animés se repeignent à chaque image sur le fil principal, et des images-clés qui contiennent `var()` y tournent aussi. La lueur du bouton DUEL animait sa `box-shadow` : 13 points de fil principal sur 17, 60 repeints par seconde, et elle écrasait le biseau de la plaque ; elle est désormais un calque frère (`.duel-lueur`, derrière la plaque dans `CombatButton`) dont seule l'opacité respire. Le dé qui roule coûte ~0,3 point ; l'arène vivante ~3-4 points (reflets et brume : `var()` dans leurs images-clés) plus un coût GPU (couches `mix-blend-mode: screen`).

- **Un onglet = UNE vague de requêtes** (19/09/2026, chantier latence ; mesures dans `docs/latence.md`). Chaque aller-retour Supabase coûte ~60 ms depuis cdg1 : ce qui dépend d'une autre lecture y est **chaîné** (`profileP.then(…)`) au lieu d'attendre toute une vague ; les **catalogues identiques pour tous** (badges, bannières, objets, capsules, quiz par matière) viennent du cache serveur (`lib/vitrines-server`, `lib/catalog`, client anon) ; les écritures dont l'écran n'attend rien partent dans `after()`. **Jamais de lecture sans filtre qui compte sur la RLS pour trier** : la policy s'évalue ligne à ligne sur la table de TOUS les élèves (le carnet filtre par `carnet_courses!inner(owner_id)`). La série se lit par `jours_actifs()` (`lib/jours-actifs`), jamais par quatre tables sur 400 jours. Un `.in()` de plus de ~150 identifiants se découpe (taille d'URL, `lib/questions/server`). Une Server Action qui ne change que l'écran courant appelle `refresh()`, pas `revalidatePath` (qui jette tous les onglets préchargés).

Testé par CDP (worker actif, page revue servie sans réseau, page inconnue → coquille) — ⚠️ l'émulation hors-ligne de CDP est PAR CIBLE (page et worker), et un profil Chrome dans un chemin long casse le CacheStorage (MAX_PATH).
